# 공동 설계 토론 (debate)

Claude와 Codex가 같은 중립 입력으로 **각자 조사·설계한 뒤** 동결·공개·토론·통합한다. 옵션 없음은 A안, `--frozen-critique`는 B안(서로의 비평도 동결 후 공개, 큰 아키텍처 결정용)이다. 결과는 설계 제안일 뿐 구현 승인이 아니다. 사용자가 결정한 뒤 기존 흐름(architect → 승인 → 구현 → 리뷰)으로 넘어간다.

실행기: `S={{SKILL_DIR}}/scripts/co_design.py`. 모든 명령은 JSON 한 줄을 출력하고, 거부·미완료는 종료 코드 2다. 상태는 `python3 $S status --session <sid>`로 본다. 작업 루트(PROJECT)는 **실행 cwd**다(프로젝트 루트에서 실행한다). cwd를 확정할 수 없을 때만 설치 설정의 `project_root`(`{{PROJECT_ROOT}}`)를 쓰고, 환경변수 등으로 바꿀 수 없다. cwd가 `/`·홈·그 상위·임시 영역의 루트처럼 너무 넓거나 홈 아래 숨김 디렉터리(`~/.claude`·`~/.codex` 등) 안이면 모든 명령이 REFUSED다.

- 초안(L1): 메인이 현재 PROJECT의 `.local/cross-check-drafts/<unique>/` 같은 새 일반 초안 디렉터리를 준비하고 `python3 $S ledger scaffold --session <sid> --stage pre-debate|final --out <초안 절대경로>`, `python3 $S synthesis scaffold --session <sid> --out <초안 절대경로>`를 실행한다. 반환 `draft` 경로의 내용을 채워 `validate --file`로 제출하며 최종 저장 경로를 재구성하거나 직접 Write/copy하지 않는다. final 초안은 Codex의 비평·응답·stance를 원문 그대로 넣는다(새 Codex 비평은 `title`=claim, Codex `position`=alternative, codex turn `text`=claim, 응답은 Codex `position`·turn `text`=argument). Claude stance는 `pending`, Claude answer·critique `text`는 빈칸, synthesis 초안은 `adopted_from`·`decision`·`reason` 빈칸과 metrics `-1`이므로 **채우기 전에는 validate가 거부한다**. 기존 파일·보호 경로·심볼릭 링크 경로에는 scaffold가 쓰지 않는다. `--out` 없는 기본 출력(`artifacts/ledger.<stage>.draft.json`·`artifacts/synthesis.draft.json`)과 `--file` 없는 기존 validate는 호환 유지하지만, 기본 초안은 ARTIFACT_ROOT 안이므로 `--file` 입력으로 사용할 수 없다. 새 권장 흐름은 처음부터 별도 일반 초안에 `scaffold --out`을 쓰는 것이다.
- scaffold 응답의 `hints`는 알려진 E/X·쟁점 ID, 입력별 줄 수·정규 인용 예시, 스키마 enum 선택지만 제공한다. stance·importance·agreement·verification·metrics·adoption은 근거를 보고 직접 결정한다. `freeze --normalize-refs`와 `ledger validate --normalize-refs`는 지정 인용 필드 전체가 `brief.md:2`·`brief:2`처럼 일대일 해석 가능한 경우에만 `brief:L2`로 고치고 입력 범위를 검사한다(scope/index도 지원). 자유 문장·알 수 없는 E/X ID는 바꾸지 않는다. freeze는 기존 원본 경로·생성 시각·상태 검사를 먼저 적용하고 원본 파일을 고치지 않는다. 엄격 검증이 모두 통과할 때만 저장하며 `artifacts/format-revisions/`에 원본 UTF-8·해시·필드별 변경을 남긴다. 옵션 없는 검증·freeze는 기존 동작이다.
- `synthesis validate --derive-checked`는 누락/임의 `codex_checked`를 실제 fidelity의 faithful 판정·요청 coverage·현재 **전체** ledger/synthesis 내용 해시로만 산출한다. 나머지 구조·의미 검증이 모두 통과한 뒤 원자 저장하고 같은 원본/변경 기록을 남긴다. 검증 실패 시 원본은 그대로다. round2·distorted·비요청 쟁점·판정 뒤 내용 변경은 true로 승격하지 않는다. 옵션 없는 validate의 허위 true 거부는 유지한다.
- 입력 압축(L3, 관련 쟁점 선별은 기본 꺼짐): `init --compact`로 세션 단위로 켠다. JSON 블록 minify, 공개 차이의 중복 인용을 ID로, 조건부 호출(fidelity/round2)은 대상 이슈와 그 이슈가 언급하는 이슈만 원장·결정·이전 출력에 남긴다(`EXCERPT FILTER` 블록에 생략 ID·해석 못한 `ledger:` 참조 표시, synthesis는 원래 줄 번호 유지, Codex 이전 출력과 같은 원문은 `@same-as <위치>`로 참조). 제안 내용(입장·단서·근거 매핑)은 그대로다. `python3 $S measure-request --session <sid> --phase <phase>`는 기존 산출물로 압축 전후 request 바이트와 추정 토큰(ASCII 4자≈1, 비ASCII 1자≈1의 오프라인 근사)·손실 검사를 출력한다(읽기 전용, 잠금·저장·모델 호출 없음). request 크기는 Codex 실제 입력 토큰(시스템 지시·도구 대화 누적 포함)의 일부 지표일 뿐이다. 채택 여부는 실측 후 사용자가 정한다.

## 기본 효율화 (새 세션 `request_format=lossless-v1`)

- 새 세션은 JSON minify·동일 요청 내 중복 원문 참조를 기본 적용한다. 최초 제안·쟁점·조건·이전 출력의 내용은 보존한다. 기존 `--compact`는 별도 선택이며 기본값으로 켜지 않는다. 형식 필드가 없는 과거 세션은 원래 방식대로 동작한다.
- 새 세션의 `fidelity_format=fidelity-json-lines-v1`은 fidelity의 numbered SYNTHESIS JSON에서 **문자열 밖 문법 공백만** 줄인다. 원래 줄 수/번호·문자열 내 공백/개행 escape·전체 JSON 값이 동일하고, 양측 최초안·원장 모든 쟁점·모든 결정·이전 출력·조건·위험·근거·통합안 global 필드를 그대로 전달한다. 의미 있는 원문을 선별 생략하지 않는다. 새 직렬화가 더 작지 않으면 기존 전체 입력을 선택한다. 일반 lossless 검사는 완화하지 않고 별도 직렬화 검사에서 원본 줄별 변환·연속 줄번호·재조립한 전체 JSON 동등성 및 나머지 블록 동일성을 확인한다. 실제 전송한 결정 전문으로 coverage를 저장하고 전체 ledger/synthesis 내용 해시 바인딩을 유지한다. 호출의 `fidelity_serialization`에 적용 여부·줄 매핑/동등성 검사·fallback 이유를 기록한다. 이 필드가 없는 세션·명시 compact·round2·최초 조사·호출 조건/한도는 기존 방식이다.
- 최초 독립 조사량·모델·추론·근거 확인·검증·안전 규칙을 줄이지 않는다. 양측 최초안 동결 후에만 재사용한다. `reveal`의 `reusable_evidence`는 Codex의 완료된 `nl -ba`·`sed -n 'a,bp'`·`head -n N`·`cat` 관측 출력과 파일 해시·인용 범위를 대조한 원문이다. 이 reader를 개행·세미콜론으로 나열한 여러 파일 읽기도 모든 참여 파일의 관측 해시와 전체 출력(줄 번호·빈 줄·마지막 개행 포함)이 현재 원문으로 재구성한 결과와 정확히 일치할 때만 지원한다. reader는 파일당 하나의 경로를 받으며 명령 16개·합계 원문 4MiB 안에서 처리한다. mention·파이프·조건 연결·리다이렉션·변수·임의 명령·지원 밖 옵션·불명확한 출력·일부 파일의 관측 해시 누락은 재사용하지 않는다. Claude는 이 산출물을 볼 수 있지만 사용 직전 현재 파일 해시를 대조하고 변경·누락·충돌·문맥 부족이면 해당 원문을 다시 조사한다. 원자적 스냅샷으로 해석하지 않는다.
- 후속 Codex 입력에는 현재 파일을 다시 대조한 `VERIFIED REUSE EVIDENCE`를 선택 첨부한다. `reuse=false`는 역사적 캡처/재사용 불가다. Claude 원문 캡처는 별도로 보존하며, 재사용 상태는 현행 코드의 사실 검증과 구분한다. 추가 묶음은 기존 근거 첨부 후 남는 용량에만 넣고, 부족하면 미첨부를 알린다. 원래 코드 조사·원문 첨부를 재사용 묶음 때문에 생략하지 않는다.
- fidelity는 전달된 입장·조건·근거·잔여 위험의 **대표성 확인**만 한다. 코드 재조사·설계 재논쟁을 시작하지 않으며 판단 자료가 부족하면 INCOMPLETE다. 기술적 정확성 검증을 완료했다고 보고하지 않는다.

## 절차

진행은 runner `status`와 짧은 보고로 확인하며 내부 P0~P5를 별도 Task 목록에 중복 등록·갱신하지 않는다. 명시 요청·기존 상위 개발 작업 연결에 필요한 Task는 유지한다.

`init` 응답의 `project_root`를 절대경로 기준 `WS`로 사용한다. 메인의 인계 원본·prepare 출력·부분 초안 `--out`/`--partial-file`은 `$WS/.local/cross-check-drafts/<unique>/...json` 형태의 실제 절대경로로 지정한다. 고유 디렉터리는 먼저 준비하고 `<unique>`는 실제 값으로 바꾼다. 이 안내는 기존 PROJECT·보호 경로·새 파일 검사를 완화하지 않는다.

원장·통합안은 scaffold를 먼저 만들고 **반환 `draft`를 Read한 뒤** `hints`와 `full_base`/Claude slot을 확인해 편집한다. scaffold가 이미 만든 파일을 읽기 전에 새 파일처럼 Write하지 않는다. `hints`·`full_base`·`claude_turn_slots`는 응답 메타데이터이며 draft 안에 복사하지 않는다. 부분 제출은 반환된 envelope를 유지하고 `hints.partial`의 허용 필드만 채운 뒤 반환 `next` 명령으로 제출한다. 기존 placeholder 쟁점은 `issues`로 수정하고 `add_issues`는 새 ID에만 사용한다. 아래 권장 명령은 인용 정규화·checked 산출 옵션을 명시하며, 옵션 없는 기존 CLI의 엄격 거부 동작은 유지한다.

**P0의 준비와 조사를 구분한다.** 메인은 P0~P1-b에서 본문 조사를 하지 않고, 최초 조사는 ready 뒤 새 architect만 맡는다. 메인의 코드·원문 대조는 P2 공개 뒤에 수행한다. 이번 실행 중 선행 코드 읽기를 발견하면 중단·보고하며 새 자식으로 위반을 덮지 않는다. 기존 컨텍스트에 있던 이력의 공개·격리와 이번 실행의 새 조사를 혼동하지 않는다. 사용자 제공 사실·요구사항·규칙과 이미 알려진 경로/메타데이터로만 입력을 작성한다. 필수 AGENTS·스킬·스키마 및 경로 존재·브랜치/커밋·변경 파일명/상태 확인은 허용한다. 대상 코드·테스트·관련 diff/로그·구현 문서 본문 읽기/검색, 외부 조사, Claude 설계 초안과 조사 에이전트 시작은 P1-a 완료 검사 전에는 하지 않는다. 입력을 채우기 위해 그 조사가 필요하면 범위·가정을 사용자에게 먼저 질문한다. 기존 컨텍스트에 관련 조사나 결론이 있으면 이를 알리고 P1-b의 새 architect 입력에서 격리한다. 이미 읽었다는 이력을 지우거나 역사적 무오염을 주장하지 않는다.

- `call`은 최대 900초(proposal)·600초(그 밖)에 버전 확인이 더해지므로 Bash 도구의 `run_in_background`로 실행하고 완료 알림을 기다린다. 포그라운드 타임아웃으로 러너가 끊기면 안 된다.
- `investigation-ready`는 기존 세션 잠금만 읽기 전용으로 획득한다(잠금 파일이 없거나 다른 명령이 실행 중이면 거부). `CODEX_PROPOSED`·proposal 종료 시각·`execution=ok`·완전한 호출 기록·동결 입력과 첨부 원자료·비공개 result/links의 기록 해시를 확인한다. 기본 성공 출력은 sid·호출 번호/종료 시각·모델 상태와 중립 입력/원자료 경로·해시뿐이며 모델 INCOMPLETE일 때만 일반 caveat를 추가한다. 제안 내용·요약·problems·로그·결과 경로를 공개하지 않는다. 모델 호출·재시도·stale 회수·세션/산출물 변경·새 토큰/상태 저장은 하지 않으며 기존 freeze/evidence 검증도 완화하지 않는다. 선택 `--architect-prompt`는 모든 검사 통과 후 같은 잠금 안에서 검증된 중립 경로·해시와 고정 출력 계약·schema 경로만 사용한 `architect_prompt`·`architect_prompt_sha256`을 추가한다. 자유문장 인수·메인 설계·실제 코드·Codex 제안은 받거나 넣지 않는다. 메인은 문자열을 그대로 전달하고 임의로 보완하지 않는다. 이 검사와 문서 순서는 Claude의 실제 Read/Bash 사전 차단이나 과거 조사 이력의 검증을 보장하지 않는다.
- 순서가 맞지 않는 명령, 세션 잠금 중 동시 명령은 거부된다. 거부를 다른 명령·경로로 우회하지 않는다.
- `call`은 Codex 기동 직후 pid/pgid를 세션에 기록한다. SIGTERM·SIGHUP·SIGINT는 플래그로만 받고(2회째부터 무시) 0.1초 감시 루프에서 프로세스 그룹을 종료한 뒤 STOPPED(EXEC)로 남긴다. SIGKILL 등으로 러너가 죽어 `running` 기록이 남으면, 다음 잠금 명령이 남은 Codex 그룹을 종료(기록한 codex 경로와 `ps -ww` 명령행이 일치하고 시작 시각이 기록과 5초 이내일 때만)하고 STOPPED(EXEC, runner terminated during call)로 바꾼다. 그 명령은 거부하지만 `finalize`는 그대로 진행해 보고한다.
- `allowed_paths`·`excluded_paths`는 프롬프트로 전달하는 **권고**일 뿐 러너가 강제하지 않는다. 강제되는 것은 `allowed_tools`와 아래 감시 항목이다.

**별도 초안 경로:** 메인이 처음부터 `<workspace>/.local/cross-check-drafts/<unique>/proposal.json` 같은 새 일반 파일에 작성한다. 예를 들어 `{{PROJECT_ROOT}}/.local/cross-check-drafts/<고유 디렉터리>/proposal.json`이다. 이 소스는 `ARTIFACT_ROOT` 전체(`{{PROJECT_ROOT}}/.local/co-design/`, 그 안의 `work/` 포함)와 `USER_TMP/co-design-*` 밖이어야 한다. `freeze --file`의 기존 보호 검사·생성 시각 검사는 유지하며 전역 TMP 환경을 바꾸지 않는다. 최종 `artifacts/claude/proposal.json`은 runner만 생성한다. 그 target이 이미 있으면 수동 삭제·덮어쓰기·자동 새 세션으로 우회하지 말고 보고 후 중단한다. B안의 Claude 비평을 동결할 때도 별도 일반 초안을 쓰는 동일 경로 규칙을 적용한다.

**원장·통합안 저장:** `ledger validate --file`·`synthesis validate --file`의 초안은 현재 runner의 PROJECT 안에 있는 절대경로의 일반 파일이어야 한다. 다른 PROJECT·다른 세션의 산출물·보호 경로·심볼릭 링크와 ARTIFACT_ROOT 전체·USER_TMP의 `co-design-*` 입력은 거부한다. runner는 구조·의미·참조·명시한 정규화/checked 검증·조건부 계산을 마친 뒤 명시한 `--session`의 `artifacts/ledger.json`·`artifacts/synthesis.json`만 원자 저장하고 실제 `path`·`sha256`을 반환한다. 메인은 그 반환값을 사용하며 최종 출력 디렉터리를 계산·직접 Write/copy하지 않는다. 원본 초안은 바꾸지 않고 의미 있는 내용·문자열·대안·조건·근거·위험은 보존하며, 명시적 인용 정규화와 derived checked 필드만 기계 변경한다. 실패하면 canonical·동결본·audit·세션을 저장하지 않는다. pre-debate 동결본은 덮어쓰지 않으며 허용 상태의 final 원장·통합안은 다시 검증해 갱신할 수 있다. `--session`은 명시 대상일 뿐 같은 스키마 내용의 원래 의도까지 증명하지 않고, 다중 파일 crash transaction이나 outer Claude의 Write 경로 강제 차단도 보장하지 않는다. 잘못된 위치의 쓰기를 발견하면 삭제·이동·덮어쓰기나 새 세션으로 조용히 복구하지 말고 위치·상태를 보고한 뒤 추가 지시를 기다린다. 첫 보호 거부 때에는 아래 중단 규칙이 그대로 우선한다.

**선택적 부분 제출:** `ledger scaffold --partial --stage pre-debate|final --session <sid> --out <새 별도 JSON 절대경로>` 또는 `synthesis scaffold --partial --session <sid> --out <새 별도 JSON 절대경로>`로 시작한다. 새 partial 모드는 현재 PROJECT 안·세션 저장소 밖의 새 `--out`을 필수로 요구한다. runner는 전체 base를 세션의 고정 private `work/partial-bases/`에 배타 저장하고 그 hash를 세션에 기록하며, 반환 `full_base`·`claude_turn_slots`를 보고 별도 draft의 변경 필드만 채운다. `session, kind, stage, base_id, base_sha256`은 바꾸지 않고 `ledger validate --stage <stage> --session <sid> --partial-file <draft>` 또는 `synthesis validate --session <sid> --partial-file <draft>`로 제출한다(`--file`과 배타). 생략한 필드는 base 그대로 보존한다. base 파일 경로·JSONPointer·배열 index·출력 경로를 제출로 지정할 수 없다.

- ledger의 `issues`는 `{issue_id, set?, turns?, add_turns?}` 배열이다. `set`은 `type, importance, title, requirement_ref, claude, decision_method, verification, status`만 받으며 `claude`·`verification`도 필요한 하위 필드만 지정할 수 있다. `turns`는 반환된 Claude `slot`과 `set`(`text, evidence_ids, would_change_if`)만 받는다. 새 Claude turn은 `add_turns`에 기존 전체 turn 형식으로, 새 Claude 쟁점은 `add_issues`에 `issue_id`와 같은 허용 필드 및 `turns`로 명시한다. 새 쟁점의 origin과 빈 Codex 입장은 runner가 만들며 메인이 Codex 입장·stance·turn 원문·근거·would_change_if를 만들거나 수정/삭제하는 경로는 없다. 선택 `states`는 명시한 하위 필드만 갱신한다. final base는 현재 Claude 답변·판정·내용을 유지하고 Codex 결과의 비평/응답 원문을 보강한다. 새로 반영한 각 비평 occurrence에는 별도 빈 Claude 답변 slot이 생기며 채우기 전에는 전체 검증이 거부한다.
- synthesis의 `decisions`는 `{issue_id, set}` 배열이며 기존 decision 필드 중 `issue_id, codex_checked`를 제외한 것만 지정한다. 새 decision도 같은 형식으로 명시하고, `remove_decisions`에 기존 ID를 명시해 미해결로 전환할 수 있다. root `set`은 `required, optional, user_decisions, unresolved, useful_from_codex, useful_none_reason, metrics`를 기존 스키마 형식으로 받는다. 명시 `conditions` 교체·철회 등 판단 변경은 허용하며 합쳐진 전체 내용으로 기존 검증·조건부 판정·fidelity를 거친다. `codex_checked`는 제출할 수 없고 runner가 실제 fidelity coverage와 전체 내용 hash로 항상 derive한다. 내용이 바뀌면 이전 checked가 승계되지 않는다. 초기 빈 decision·metrics sentinel도 이 필드들로 채운다.

부분 제출도 합친 전체 후보에 기존 schema·의미·근거·조건부·checked/finalize 검증을 적용한 뒤 같은 canonical 저장/preflight를 사용한다. legacy 원장에 Codex 비평/응답 원문 turn이 없으면 그 원문을 보강하고 비평별 빈 답변 slot을 추가한다. 기존 답변은 보존하되 그것이 누락 원문의 비평까지 답했다고 추정하지 않으며 새 slot을 채워야 한다. 같은 원문 occurrence가 이미 canonical에 있으면 새 scaffold가 답변을 초기화하거나 빈 slot을 반복 추가하지 않는다. 알 수 없는 필드/ID·중복 issue/decision operation·잘못된 slot·Codex 수정은 저장 전에 거부한다. canonical·동결/근거·관련 Codex 결과·단계가 base 생성 후 바뀌면 `INVALID: stale partial base`인 일반 optimistic conflict로 반환한다. 자동 rebase나 옛 patch의 무조건 재적용은 하지 말고, 반환 next대로 새 base를 받아 변경 근거를 확인한 뒤 다시 제출한다. 성공 후 추가 변경이나 fidelity 뒤 재derive도 새 base에서 시작한다. 같은 trusted base의 내용은 canonical/의존성이 그대로일 때만 다시 사용할 수 있다. base 변조·훅/permission/보호정책 거부는 일반 stale 충돌과 다르며 아래 첫 거부 중단 규칙을 따른다. B안 독립 Claude 비평의 pre-freeze는 기존 full `freeze --side claude-critique`로 유지하고, B안 final 원장·synthesis는 부분 제출을 지원한다.

**구조화 architect 인계:** P1-b 위임에 [출력 계약·전체 예제·원본 보존/오류 처리](architect-handoff.md)와 `scripts/debate/schemas/proposal.schema.json` 경로를 포함한다. 일반 architect Markdown 형식 대신 JSON 하나로 반환하며 `design.components/flows/contracts`는 `string[]`, 비파일 근거는 `E<n>`이다. 새 메시지는 정확히 `{handoff_version: 2, proposal: <기존 proposal.schema.json의 전체 object>, evidence_manifest: [...]}`다. 관찰문은 proposal의 evidence에만 한 번 작성하고 manifest에는 넣지 않는다. proposal의 side는 `claude`이며 요구사항·설계·대안·조건·위험·검증·미확인·부가 설명을 모두 기존 필드에 담는다. file 근거의 `id`는 `local:source_a` 같은 로컬 키, `ref`는 실제 `relative/path:L1-L2` 또는 절대경로의 같은 범위이고, manifest 각 항목은 정확히 다음 필드를 갖는다.

```json
{"key":"local:source_a","path":"/absolute/current/project/src/file.py","lines":[1,2],"file_sha256":"현재 전체 파일 sha256","source_state":{"worktree":"/absolute/current/project","checked_at":"2026-11-17","status":"Git 여부·branch/commit·관련 로컬 변경 또는 Git 미사용"}}
```

모든 file 근거는 유일한 manifest와 일치해야 한다. v2의 관찰문은 proposal.evidence[].observation 원문 하나를 local key로 연결해 등록 entry에 그대로 복사한다. 문장 생성·요약·비교 판단은 하지 않는다. 무태그 legacy 형식은 기존처럼 양쪽 observation을 요구하고 정확히 일치해야 하며, 불일치한 옛 메시지를 자동 변환하지 않는다. runner는 현재 PROJECT의 파일·범위·현재 hash·관찰 매핑을 검사한다. `source_state.worktree`는 PROJECT 자체 또는 해당 파일을 포함하는 PROJECT 안의 실제 하위 작업트리(app/edge 등)이며 보호 경로·외부·심볼릭 링크는 허용하지 않는다. `source_state.status`는 architect가 보고한 저장소별 상태이며 git 내용까지 자동 인증하는 값이 아니다. 기존 등록 command/mcp/web의 kind·ref와 비등록 brief/inference·선택 data 원자료 참조는 기존 의미 그대로 유지하고 file로 승격하지 않는다. 기존 semantics가 요구하는 등록이 없는 command/mcp/web는 계속 거부한다. 로컬 키는 선언된 evidence `id`에서만 정확히 변환하고 자유 문장/ref에 로컬 키가 남으면 추측 치환 없이 등록 전에 거부한다. 기존 등록 ID와 비등록 proposal ID를 함께 예약해 새 ID가 충돌하지 않으며 이후 `evidence add`도 같은 예약을 따른다. 메시지/전체 schema·생성 시각·전건 capture·별도 새 출력 경로 검사를 끝내기 전에는 근거·초안·세션을 저장하지 않는다. prepare 뒤 기존 freeze는 메인만 실행한다. 실제 Agent 완료 응답의 `output_file`이 빈 문자열이므로 메인이 메시지 JSON을 한 번 저장하는 복사는 남는다. transcript 전역 검색·새 Claude subprocess·architect 파일 쓰기·별도 raw notes 보관으로 우회하지 않는다. 재작성·ID 오류·Codex 원문 전사를 줄이려는 기능이며 실제 절감이나 조사/추론 품질 동등성을 측정한 것은 아니다.

**거부 처리:** 첫 훅·permission·보호정책 거부부터 현재 workflow를 중단하고 사용자에게 보고한다. 자식은 즉시 메인에 알리고, 메인도 추가 호출·동결·정리를 실행하지 않는다. `rm`→`rm -f` 같은 flag 변경, 다른 명령/도구/경로/프로필 사용, 설정 변경, 기존 요청을 삭제 승인으로 해석, 자식이 거부당한 동작을 메인이 대신 실행, 다른 새 세션을 통한 우회도 하지 않는다. 훅·permission·보호정책 거부에는 이 중단 규칙이 P5와 stale 회수 뒤의 `finalize` 안내보다 우선한다. 이 경우 `finalize`·새 보고서 파일 생성도 중단하고 허용된 기존 기록·`status` 조회와 채팅 보고만 한다. 보호 거부가 아닌 다른 STOPPED의 기존 보고 절차와 runner의 `finalize` 기능은 유지한다. architect 인계 오류는 [원본 보존 규칙](architect-handoff.md)에 따라 수정하지 않고 중단·보고한다. 그 밖의 보호 거부가 아닌 로컬 초안 schema·줄 범위 입력 오류(원장·통합안 등)는 원인을 확인한 뒤 수정할 수 있지만, 동일 실패 2회 뒤 새 근거 없이 반복하지 않는 기존 규칙은 유지한다. 거부 분류가 불명확하면 중단·보고한다. 이 지침은 outer Claude의 도구 실행을 강제 차단하거나 실제 준수를 증명하지 않으며 별도 설정/훅을 추가하지 않는다.

## 최종 보고 형식 (A·B안 공통)

- 채팅 최종 보고는 최초 제안 비교표·쟁점별 토론/결론 표·사용자 결정/미해결을 중심으로 짧게 쓰고 상세 `report.md` 경로를 연결한다. 보고서 1~10절을 다시 풀어 쓰지 않되 중요한 조건·위험·미검증·Codex 확인 상태를 생략하지 않는다.
- 사용자에게 보고할 때 `report.md` 1절의 **최초 제안 비교표**를 먼저 보여준다. 분량에 맞춰 요약하되 양쪽 핵심 제안·차이·중요 전제와 미확인을 보존한다. 원본은 토론 전 동결한 `artifacts/claude/proposal.json`·`artifacts/codex/proposal.json`이다. 최종 원장 입장을 최초안으로 바꾸어 쓰지 않는다.
- 이어서 기존 원장·통합안으로 아래 **쟁점별 토론·결론 표**를 작성한다. 중요 쟁점마다 한 행을 쓰고 상세 내용은 보고서의 같은 쟁점 ID로 연결한다.

  | 쟁점 ID·내용 | Claude 최초 입장 | Codex 최초 입장 | 상대 지적·응답 요약 | 최종 제안·변경 이유 | 합의·미해결 / Codex 확인 |
  | --- | --- | --- | --- | --- | --- |
  | 원장 ID·쟁점 | 최초안 근거 위치와 요약 | 최초안 근거 위치와 요약 | 누가 무엇을 지적하고 어떻게 답했는지 | 유지·수정·기각·통합 결과와 이유 | 원장 상태와 Codex 확인 여부를 구분 |

- 최초안에 없는 쟁점은 `최초안에 명시 없음(토론 중 추가)`, 한쪽 산출물이 없으면 `미작성/확인 불가`로 쓴다. 제안 항목의 순서나 비슷한 표현만으로 같은 쟁점이라고 짝짓지 않으며, 연결을 확인할 수 없으면 `대응 미확인`으로 남긴다. 합의와 사실 검증·Codex의 통합안 확인은 구분한다.
- 두 표는 기존 산출물로 작성한다. 표를 채우기 위한 추가 모델 호출·토론은 하지 않는다. `--review`·`--test-plan`·`--code-review`에는 독립 최초안 두 개가 없으므로 이 형식을 강제하지 않는다.

## 원장 규칙 (`ledger.schema.json`)

- 근거 연결(`*_links.json`·summary `links`): 파일 인용(`path:Lx-Ly`)은 같은 세션의 **완료된** 셸 도구 기록이 같은 파이프라인 안에서 그 파일의 해당 범위를 읽었고(`sed -n 'a,bp' 파일`, `nl`/`cat 파일 | sed -n 'a,bp'`, `head -n N 파일`, 범위 지정 없는 `cat`/`nl` 전체 읽기, 또는 `rg -n`/`grep -n` 출력에 해당 줄 번호 전부) 출력이 인용 범위 줄 수 이상이면 `excerpt`, 그 밖의 경로 일치는 `mention`이다. 읽은 뒤 후단에 `head`·`tail`·`grep` 등 필터가 있거나, 범위가 다른 파이프라인(`&&`·`;` 뒤)의 것이거나, 출력이 비었으면 `mention`이다. 등록된 Claude 근거(`E<n>`)와 그 범위 안 인용은 `excerpt`, URL·자유 문구는 `mention`. 기존 `linked` 키는 `excerpt + mention`으로 유지한다.

- 쟁점 ID는 `I<n>`(Claude)·`C<n>`(Codex 비평) 등 대문자+숫자이며 Codex 출력의 `issue_id`와 같게 쓴다. 입장은 `pending|proposed|accept|reject|conditional|open`, 판정 방법은 `pending|source-text|reproduction|user-decision|undecidable`이다.
- high·medium 쟁점은 최종 단계에서 양측 stance와 판정 방법이 모두 있어야 한다. `type=fact`는 사용자 결정으로 판정하지 않으며, confirmed/refuted에는 방법과 근거 ID가 필요하다. 근거 ID는 등록된 `E<n>`, Codex 제안의 `X<n>`, `brief:Ln`·`scope:Ln`·`index:Ln`만 쓴다.
- Claude가 실행한 결과는 관찰 출처의 하나일 뿐이다. 두 AI의 합의는 증거가 아니며 합의율·채택률을 품질 지표로 쓰지 않는다.
- 상태는 실행(`states.execution`)·근거 충분성·합의를 분리해 기록한다.

## 조건부 호출 판정

1. `round2`: 토론 후 등록한 새 근거로 high 쟁점의 verification·status가 바뀌었거나 사용자가 요청(`--user-requested`).
2. `fidelity`: 1이 아니면서 high 쟁점이 통합안에서 빠짐, Codex 최종 stance가 accept가 아닌데 Codex 안 이외(`claude`·`both`·`neither`·`evidence`)를 채택, ledger의 Codex stance가 Codex 출력과 다름, Codex의 조건부 입장이 결정 조건에 없음. 계획의 "토론 후 Codex 입장의 잔여 위험 변경" 비교는 구현하지 않았다(잔여 위험은 자유 서술이라 기계 비교 불가). 해당하면 사용자 요청(`--user-requested`)으로 round2를 쓰거나 미확인으로 보고한다.
3. 둘 다면 round2 먼저. 예산(호출 상한·Codex 누적 예산 잔여 60초 미만·이미 사용)이 없으면 `next=none`, `blocked`에 이유가 남는다. 계산된 이유가 없거나 통합안·ledger가 계산 뒤 바뀌었으면 호출이 거부된다.

## 실행 한도·정지

- 호출 상한 A안 3회·B안 4회(실패 포함, 자동 재시도 없음). **시간 제한은 Codex 쪽에만 둔다(토큰 사용량 제한 목적).** 호출 timeout은 `min(단계 상한, Codex 누적 예산 잔여)`이며 단계 상한은 proposal 900초, 그 밖 600초다. Codex 누적 예산은 A안 1800초·B안 2400초로, 종료된 호출의 Codex 프로세스 실행 시간(`codex_seconds`, 실패 포함) 합계로 센다. Claude의 조사·작성 시간은 세지 않으며 제한하지 않는다. 잔여가 60초 미만이면 필수 단계는 `BUDGET_EXHAUSTED`로 정지하고 조건부 단계는 거부된다. 최악의 경우에도 필수 단계는 예산 안에 든다(A 15+10분, B 15+10+10분). 누적이 예산에 도달하면 `over_budget`으로 기록하고, 전체 경과 시간은 참고값으로만 보고한다. 토큰은 호출 종료 시에만 보고되므로 실시간 제한은 시간으로 건다. 이전 방식(`deadline_at`) 세션도 계획 기본 예산으로 동작한다.
- Codex 실행: `codex exec --sandbox read-only --skip-git-repo-check --ephemeral -C <작업 루트> --json --output-schema … -o … -c features.…=false -`. 모델·프로필·사용자 설정 무시·규칙 무시·위험 옵션·디렉터리 추가·resume은 넘기지 않는다. `-c`는 코드 상수인 도구 비활성화 키만 쓴다.
- 요청은 192KiB 이하(넘으면 자르지 않고 INCOMPLETE, 호출 수에 포함 안 됨), 결과 128KiB, 로그 8MiB, 도구 호출 60회, 누적 도구 출력 4MiB.
- 요청이 192KiB를 넘어 정지될 때에 한해 debate·critique·rebuttal 단계는 minify·중복 ID화만 하는 compact로 다시 만들어 들어가면 그 호출만 compact로 보낸다(호출 기록 `auto_compact`). 쟁점을 발췌하는 round2·fidelity에는 적용하지 않는다. 그래도 넘으면 위와 같이 INCOMPLETE다. compact 상시 채택(`init --compact`)은 여전히 사용자 결정이다.
- proposal 이후 요청에는 Claude 근거 `E<n>`의 동결 원문(`CLAUDE EVIDENCE CAPTURES`, 합계 96KiB와 요청 잔여 용량(여유 4KiB) 중 작은 값까지, 넘는 ID는 생략 표시)을 싣는다. 작업 루트 밖 근거도 경로를 열지 않고 원문으로 확인한다. round2의 새 근거는 기존대로 `NEW EVIDENCE SINCE DEBATE`로 보낸다.
- scope의 `allowed_tools`에 `web`이 있을 때만 `codex --search exec …`로 web_search를 켠다. 검색어 내용은 비밀 경로 마커 외에는 검사하지 않으므로 `external_transfer` 판단에 의존한다.
- 결과 형식 완화(2026-10-26): Codex 자신의 ID가 형식만 어긋난 경우(`x1`·`X-01`·`C-1`)는 정규형으로 고치고 결과 안 같은 문자열 값도 맞춘다(`normalized_ids`, 원문은 `result.raw.json`). 정규화 후 충돌·중복이면 기존대로 SCHEMA다. Codex 제안의 `brief` 근거 참조 오류는 그 근거의 문제(`problems`, unbacked)로 남기고 결과를 유지한다(Claude 제안 freeze는 기존대로 거부).
- POLICY·BUDGET·EXEC 정지 시에만 그때까지의 Codex 중간 메시지를 `calls/<n>-<phase>/partial_messages.md`(UTF-8 64KiB, summary `partial_messages`)로 남긴다. 검증된 결과가 아니다. proposal 단계의 partial은 공개 전 Codex 소견이므로 사용자에게만 보고하고, 같은 질문을 다시 돌리기 전 Claude는 읽지 않는다.
- 실시간 감시(0.1초, 종료 후에는 EOF까지)로 다음을 발견하면 프로세스 그룹을 종료하고 STOPPED가 된다: 허용 목록(`thread.started`·`turn.*`·`error`·`item.*`) 밖의 이벤트, `file_change`·`collab_tool_call` 등 허용 목록 밖의 item type·알 수 없는 status, 금지 도구(codex_apps·node_repl·cua_repl·image_gen·spawn_agent), stderr.log의 hook 거부 행, 범위 명세에 없는 도구, 독립성 마커(셸 명령은 `shlex`로 구간·단어를 나눠 경로 위치의 단어만 `//`·`/./` 정규화와 대소문자 무시로 대조한다. rg/grep/ag의 검색 패턴(첫 위치 인자, `-e`·`--regexp` 값)과 find의 `-name`·`-path` 등 패턴 값은 제외하고, `-f`·`--file` 값과 find `-exec` 안 명령은 검사한다. 해석에 실패하면 전체 문자열을 보수적으로 검사한다: `.claude/projects/`(`<프로젝트>/memory` 제외), `/tmp/claude-`, `.local/co-design/`(현재 세션 `inputs/` 제외), 사용자 임시 영역의 `co-design-*`, `$TMPDIR`), 넓은 루트(`~`·`$HOME`·홈 디렉터리·`~/.claude`·`/tmp`·`/private/tmp`·`$TMPDIR`·`/var/folders`·`-C`보다 위의 `..`)를 향한 재귀·목록 도구(`grep -r`·`rg`·`find` 시작 경로·`ls`·`xargs`·`tree`·`du`·`cd` 등)나 글롭·중괄호 확장(`* ? [ {`), 도구 **출력**에 나타난 경로 형태(셸 출력 중 작업 루트 안 파일(`.local` 제외)의 실제 본문과 일치하는 줄은 본문을 빼고 `path:행:` 등 행두 경로만 검사한다. 머리글·오류·목록 줄, 작업 루트 밖·`.local` 내용, MCP 출력은 전체 검사. Claude 세션 파일 경로, `/tmp/claude-<n>/`, 세션 logs/evidence 경로, 다른 세션 산출물 경로. 단어만으로는 판정하지 않음), 비밀 경로 마커, `error`·`turn.failed`·실패한 도구의 hook 거부 문구, 상한 초과. 그 밖에 exit≠0, 결과 스키마 위반, 동결 입력 변경, Codex 버전 변경도 정지다. 독립성 마커가 나오면 결과를 폐기하고 D4 위반으로 집계한다.
- 넓은 루트 판정은 보수적이라 `cd sub && rg x ..`처럼 프로젝트 안을 가리키는 `..`도 정지시킬 수 있다. 셸 변수·명령 치환·스크립트 언어로 경로를 만들어 읽는 방식은 여전히 탐지하지 못할 수 있다.
- **E2E 실측 (codex-cli 0.162.0-alpha.2, 2026-10-08):**
  - hook 거부(E2E-1/3): 거부된 명령은 events.jsonl에 item을 남기지 않는다. 흔적은 stderr.log의 1행(`<시각> ERROR codex_core::tools::router: error=Command blocked by PreToolUse hook: <사유>. Command: …`)과 agent_message 본문뿐이다. 러너는 stderr.log도 events와 같이 0.1초마다 이어 읽어(읽기 경계에서 끊긴 행은 이어 붙여) `Command blocked by PreToolUse hook`이 보이면 POLICY로 정지한다. 실패한 도구 출력의 `HOOK_DENIAL` 검사와 `error`·`turn.failed` 정지도 유지한다.
  - 이벤트 형태(E2E-3): 최상위는 `thread.started`·`turn.started`·`item.*`·`turn.completed`(usage 포함)다. command_execution 키는 `aggregated_output, command, exit_code, id, status, type`, mcp_tool_call 키는 `arguments, error, id, result, server, status, tool, type`로 현재 판정과 같다.
  - Q2 도구(E2E-4): **가능한 것은 끄고, 나머지는 탐지 후 정지**한다. 현재 `-c features.…=false` 키로 codex_apps·image_gen·node_repl은 노출되지 않았다. cua_repl은 동봉 MCP라 계속 호출할 수 있고 `mcp_tool_call`(server `cua_repl`)로 나타나 감시가 정지시킨다(재생 확인). `-c mcp_servers.cua_repl.enabled=false`는 config 로드 오류(invalid transport)로 Codex가 기동하지 않으므로 쓰지 않는다. collaboration 도구는 `features.multi_agent`·`code_mode_host`·`goals=false`로도 사라지지 않는다. `spawn_agent`는 `--ephemeral`에서 실패하고(no rollout found), `list_agents`는 이벤트 없이 실행되며(읽기 전용 목록), `wait_agent`는 `collab_tool_call` item으로 나타나 허용 목록 밖이라 정지한다. 2026-10-09 실측으로 미사용 기능(plugins·skill_search·tool_suggest·goals·view_image·sleep_tool)도 끈다. 단일 호출 기준 입력이 약 4.6K 토큰 줄었고(21,282→16,686), 지시 로딩과 리뷰 결과는 같았다. debate는 조사에 셸이 필요하므로 `shell_tool`은 끄지 않는다(단일 호출 모드에서만 끈다).
  - 출력 잘림(E2E-5): events의 `aggregated_output`은 전체 출력을 담는다(222,600바이트 파일이 그대로 기록됨). 잘리는 것은 모델에 보이는 부분뿐이므로 출력 해시·경로 감시는 전체 출력 기준이다.
  - 읽기 범위(E2E-7, S1): `--sandbox read-only`에서도 `-C` 밖(`/tmp/...`)을 읽을 수 있다. 샌드박스는 읽기를 격리하지 않는다.
  - workdir: 셸 호출에 `workdir`를 주면 events에는 `/bin/zsh -lc 'cat fake.txt'`만 남고 cwd/workdir 키가 없다. **잔여 위험:** 작업 디렉터리를 넓은 루트로 둔 상대경로 읽기는 명령 검사로 잡지 못하고 도구 출력의 경로 형태 마커로만 잡힌다(출력에 경로가 없으면 놓친다).
- 이 감시는 실행 전 차단이 아니라 **탐지 후 중단** 등급이다. guard hook은 상대경로·난독화 명령, Claude 세션 기록·scratchpad 읽기를 사전에 막지 못한다. Codex→Claude 안은 순차 진행·완료 검사·새 architect의 중립 입력 격리와 생성 시각 검사로, Claude→Codex 안은 절차·경로 비공개·시각 기록으로 방지한다. 생성 시각만으로 조사 시점이나 Claude 도구의 실제 순서 준수를 증명하지 못한다.
- 모델이 스스로 낸 INCOMPLETE(근거 부족, 응답 누락)는 조건부로 진행한다. 정지 후에는 `finalize`로 보고만 하고 재시도·우회하지 않는다.

## 버전 게이트·보존

- `init`은 `codex --version`이 `<작업 루트>/.local/co-design/verified_codex_version`과 다르면 **자동 점검**(무해한 Codex 호출 1회, 상한 240초)을 돌리고 PASS일 때만 이 파일과 `verified_codex_version.json`(점검 시각·usage·경고·로그 경로)을 갱신해 계속한다. FAIL이면 이유와 로그 경로(`<USER_TMP>/co-design-verify-*`)를 담아 거부하고 기록은 바꾸지 않는다. `--no-auto-verify`는 예전처럼 바로 거부하고, `python3 $S verify-codex`는 지금 점검만 한다(task-metrics 기록 대상 아님, 결과 usage는 출력에 있음).
  - 점검 내용: 도구 비활성화 키로 기동(exit 0·`turn.completed`), 상위 이벤트·item type이 허용 목록 안(`error`·`turn.failed` 없음), 셸 item 키가 E2E-3과 같음(`aggregated_output, command, exit_code, id, status, type`), 비밀 경로 문자열을 `echo`하는 명령이 실행되지 않고 stderr에 hook 거부 행이 남음(Codex 업데이트로 hook 신뢰가 풀린 경우도 여기서 잡힌다). 금지 도구(cua_repl 등)가 노출되면 감시가 정지시키므로 경고로만 남긴다.
  - 점검하지 않는 것: 독립성 마커·출력 경로 판정(러너 코드 쪽 논리라 단위 테스트로 확인), `--search` 동작, 장시간 호출의 timeout 처리. 이벤트 형태가 크게 바뀐 업데이트라면 FAIL 이유를 보고 수동 E2E로 보완한다.
- 산출물 `<작업 루트>/.local/co-design/<sid>/artifacts/`는 사용자가 결정할 때까지 보관하고 자동 삭제하지 않는다(결정되면 `docs/`로 옮긴다).
- **영구 보존 `…/.local/co-design/<sid>/work/`** (Codex 금지 경로 안, 자동 삭제 없음, 사용자가 삭제): Claude 근거 발췌 `evidence/claude/E<n>.txt`, Codex 도구 기록 `evidence/codex_tools.jsonl`, 도구 원문 `evidence/codex_raw/`(누적 4MiB 상한), 호출별 `calls/<n>-<phase>/summary.json`·`result.json`·`links.json`. 세션의 호출 기록 `summary`는 이 경로를 가리킨다.
- **임시 `<USER_TMP>/co-design-<sid>/logs/calls/<n>-<phase>/`** (`request.txt`·`events.jsonl`·`stderr.log`, Codex `-o` 출력): 7일. 실측(2026-10-09): 재부팅 등으로 TMPDIR가 비면 사라진다. E2E-6 세션 `20261008T061649Z-c2b66e`의 임시 작업 디렉터리는 이미 없었다(`20261009T005927Z-ab0d59`는 남아 있었음). 그래서 reveal·round2·finalize·measure-request는 영구본만으로 동작하고, 이전 세션의 임시 경로(`evidence/`, `logs/calls/…/summary.json`)가 있으면 그것도 읽는다.
- `finalize`는 summary를 못 읽은 호출 수를 `summaries_missing`으로 보고하고, usage 합계를 `usage_status`(`complete`/`partial`/`unknown`, `unknown`이면 `usage_total=null`)로, 위반 수를 `violations_status`(누락이 있으면 `violations=null`, 관측값은 `violations_observed`)로 0과 구분한다.
- `python3 $S prune`은 목록만 출력하고, `--apply`는 사용자가 승인한 경우에만 실행해 임시 영역만 지운다(logs 7일, 이전 세션의 임시 evidence 14일). `.local/co-design`(artifacts·work)은 대상이 아니다. Codex 세션은 `--ephemeral`로 저장하지 않는다.
- task-metrics: `finalize`·`reveal` 출력의 `call_summaries`(실재하는 호출별 summary 경로)를 호출마다 `--workflow debate --cross-check-summary <summary.json>`으로 한 번씩 기록한다.
