# 중요한 구현 변경 교차리뷰

사용자가 요청한 중요 로직·권한·서비스 간 계약(토픽·스키마·식별자·데이터 포맷) 등의 변경을 검토한다. 동작에 영향 없는 사소한 편집은 별도 교차리뷰를 추가하지 않는다.

- packet에 요구사항·승인 계획·완료 기준, 비교 기준(커밋 또는 보관한 기준본), 변경 파일/의도와 변경 전후 원문 또는 diff, 관련 호출부·계약 상대측 원문을 담는다. 현재 파일의 원문은 `--include <경로>:<a>-<b>`로 붙여 출처(sha256·수정 시각·Git 상태)를 함께 남긴다. 저장소별 커밋·staged/unstaged·관련 새 파일을 구분하고 다른 작업의 변경을 섞지 않는다. Git 미사용이면 변경 목록/기준본을 쓴다.
- 실행한 검사 명령·대상·결과·환경/코드 상태와 미실행 항목을 전달한다. 관련 기존 리뷰 근거를 재사용하되 작성자의 결론만으로 판단하지 않는다. 누락된 핵심 원문은 unverified/INCOMPLETE로 남긴다.
- 요구사항 누락, 실제 버그/실패 경로/경쟁 조건, 호환성·계약, 변경 관련 보안을 우선한다. findings에는 발생 조건·영향·수정 방향·근거를 담고 확실한 버그와 의심을 구분한다. 사소한 취향 지적을 늘리지 않으며 결함이 없으면 그대로 보고한다.
- Codex 호출은 `--mode code-review` 한 번이며 제출 자료만 검토한다. 현행 `code-reviewer`와 겹치는 항목은 동일한 근거/결과를 재사용한다. 교차검토만으로 필수 코드 리뷰·테스트를 면제하지 않되, 메인은 기존 리뷰 담당에게 미확인/누락 경계만 전달하여 전면 중복 검토를 피한다.
- 수정은 기존 구현 담당이 맡고 재확인은 수정점/영향 경계에 한정한다. 추가 모델 호출·전체 재리뷰를 자동 실행하지 않는다.
