# prune-memory — memory 정기 정비

필요한 지식을 정확히 찾고 중복 읽기를 줄이도록 개인 memory를 정리한다.
인덱스를 자동으로 읽는 환경에서는 인덱스 압축도 도움이 되지만, 파일 수 감소만으로
토큰 절감을 보장하지 않는다. 실제 정비 요청이 있을 때 실행하며, 스킬 검토·수정
요청만으로 memory를 편집하지 않는다.

## 대상 확인

이 프로젝트의 기본 대상: `{{MEMORY_DIR}}/`.
두 스킬의 정리 대상이며, Codex의 자동 memory 로딩을 설정한다는 뜻은 아니다.
사용자가 다른 경로를 지정하면 그 경로를 확인한다. 대상 폴더·MEMORY.md가 없거나
대상이 불명확하면 편집을 멈추고 보고한다. 빈 memory를 만들거나 다른 폴더로 임의 전환하지 않는다.
대상은 해당 폴더의 memory Markdown과 인덱스다. 프로젝트 지침·handoff 문서·다른 프로젝트
memory·`.backup_*`는 정리 대상에서 제외한다. 환경의 보호 규칙과 승인 경계를 유지한다.

## 가지치기 3종류와 취급 (핵심)

| 종류 | 내용 손실 | 처리 방식 |
| --- | --- | --- |
| ① 통합 (관련 내용 병합) | 모든 의미 있는 정보 보존을 대조해야 함 | **정비 요청 범위에서 실행·검증·보고. 원본 제거는 별도 승인** |
| ② 압축 (인덱스 축약) | 상세 본문과 검색 단서 유지 | **정비 요청 범위에서 실행·검증·보고** |
| ③ 삭제 (원본 파일·지식 항목 제거) | 통합 후 원본 제거도 포함 | **후보 리스트 제출 → 승인한 대상만 삭제** |

## 절차

### 0. 백업 (항상 먼저)
대상 확인 후 편집 전에 memory Markdown과 인덱스를 새 `.backup_<타임스탬프>/`에
상대 경로를 유지해 백업한다. 기존 백업은 덮어쓰지 않으며 `.backup_*`를 다시 복사하지 않는다.
백업의 파일 목록과 내용이 원본과 일치하는지 확인한다. 누락·복사 실패·권한 거부가 있으면
편집하지 않는다. 백업도 자동 삭제하지 않는다.

### 1. 스캔
MEMORY.md와 대상 Markdown을 확인하되, 이미 확인한 내용은 재사용하고 큰 자료는 필요한
구간부터 읽는다. 읽지 않은 부분을 불필요하다고 판정하지 않는다.
- **통합 후보**: 주제뿐 아니라 함께 참조하는 상황도 겹치는 파일 쌍/그룹.
  서로 다른 조건에서 읽는 내용은 분리한다. 합친 문서가 커져 불필요한 읽기가 늘면
  통합 대신 인덱스·상호 참조를 개선한다.
- **압축 후보**: 인덱스가 한 줄을 크게 넘거나 밀도가 과한 포인터
- **삭제 후보**: 아래 3번 기준에 해당하는 항목

### 2. 통합·압축 실행 후 검증
- **통합**: 모든 사실·함정·결정 이유·수치·예외·적용 조건·근거를 보존한다.
  의미가 같은 중복 표현만 정리한다. 모순되는 기록은 조건·시점과 함께 남기고 임의로
  하나를 선택하지 않는다. 결과를 각 원본과 대조해 정보가 남은 위치를 확인한다.
  대조가 끝나기 전에는 통합 완료로 보고하지 않는다. 원본은 삭제 승인이 있기까지 보존한다.
- **압축**: 포인터를 짧게 하되 주제·적용 상황·중요 함정의 검색 단서를 유지한다.
  통합으로 합친 포인터는 원래 포인터의 날짜·수치·고유 키워드가 남았는지 대조한다.
  압축 대상의 개별 Markdown 본문은 바꾸지 않는다. 한 줄 맞추기 때문에 필요한 단서를 버리지 않는다.
- **참조 확인**: MEMORY.md, 대상 문서의 `[[링크]]`·표준 Markdown 링크·파일명 참조를
  확인하고 영향받는 참조를 갱신한다. 통합 결과와 백업을 대조하고 상대 경로·필요한 앵커가
  유효한지 확인한다. 대상 밖의 에이전트 지침·계획 등에 알려진 참조가 있으면 함께 점검하되,
  그 파일의 수정은 별도 권한 범위를 따른다. 해결되지 않은 참조를 남긴 채 원본을 삭제하지 않는다.
- 검증 실패 시 편집을 이어가지 말고 영향받는 변경을 백업으로 복원한 뒤 실패를 보고한다.
  검증 성공 시 통합·압축 내용, 백업 위치, 미해결 사항과 보존 중인 원본을 간단히 보고한다.

### 2-1. Codex 변경 부분 검증 (Claude에서 실행할 때만)
Claude가 정리 담당, Codex가 읽기 전용 검증 담당이다. Codex에서 이 스킬을 실행할 때는
이 단계를 호출하지 않고 위 2번 대조로 검증한다. 통합·압축·참조 변경이 없으면 생략한다.
1. Claude 자체 대조가 끝난 뒤, 통합이 있으면 대상 memory 폴더 밖의 임시 위치에 매핑 파일을 쓴다.
   내용은 통합 원본 파일명→결과 파일명과 보존 중인 원본만 적는다. 변경 파일 목록은 스크립트가 만든다.
   Claude의 자기평가·예상 정답·이전 대화는 넣지 않는다.
2. `python3 {{SKILL_DIR}}/scripts/codex_verify.py --memory <대상> --backup <이번 백업> [--mapping <매핑>]`
   를 실행한다. 스크립트는 다음을 수행하고 결과·stderr·이벤트를 보존한다.
   - 백업과 해시 비교로 변경·추가·삭제 목록 생성(변경 없으면 `NO_CHANGES`로 종료).
   - 기계적 검사: 전체 링크 유효성, frontmatter name=파일명, 전 파일 인덱스 포함. 실패 시 Codex 없이 `FAIL`.
   - 변경·추가·삭제 파일, 통합 원본, 1단계 참조 파일, `MEMORY.md`만 고정 복사해
     `codex exec --sandbox read-only`로 의미 검증. Codex는 목록이 아니라 실제 내용을 대조한다.
   모델·추론·규칙·훅은 Codex 설정 그대로 쓰며 우회 옵션을 추가하지 않는다.
   호출당 제한 시간 600초, 실행 중 진행을 주기적으로 알린다.
3. 판정: `PASS`(변경 없으면 `NO_CHANGES`)만 합격이다. 종료 코드 0만으로 합격 처리하지 않는다.
   - `FAIL`: 각 지적을 원본·결과에서 직접 확인한다. 타당한 지적을 고쳤다면 새 스냅샷으로 재검증은 1회까지.
     그래도 `FAIL`이거나 고치지 않으면 영향받는 변경을 백업으로 복원하고 지적과 함께 보고한다.
   - `INCOMPLETE`·타임아웃·인증/권한 거부: 검증 미완료로 보고한다. 다른 경로·옵션으로 우회하지 않는다.
   - 합격 전에는 해당 통합의 원본을 삭제 후보로 올리지 않는다.
4. 보고에 판정, 지적과 처리, 결과 폴더, 시간·토큰 사용량(기록된 값만)을 포함한다.

### 3. 삭제 후보 리스트 제출 (지우지 않음)
아래 기준에 맞는 항목만 후보로 올리고, **각 항목에 삭제 근거를 붙인다.**
- 통합 후 원본: 보존 내용을 대조했고 대체 문서가 있으며 참조 갱신이 완료됨.
- 이 파일이 가리키는 코드/파일/리소스가 **현재 존재하지 않음**(코드에서 검증)
- 이 결정/설계가 **다른 항목으로 완전히 대체됨**(대체 항목과 중요한 결정 이유의 보존 위치 명시)
- 이 함정이 **현재 코드에서 실제로 해소됨**(코드에서 검증 — 검증 안 되면 삭제 후보로 올리지 말 것)

**삭제 후보 제외 원칙**: 함정(트랩) 지식은 실수 재발 방지의 핵심이므로,
현재 코드에서 해소가 **검증되기 전까지 삭제하지 않는다.** 애매하면 남긴다.
해소된 함정이나 폐기된 결정도 재발 방지·역사적 이유가 필요하면 보존한다.

리스트를 표로 제출: `파일명/항목 | 삭제 종류·요약 | 근거·대체 위치 | 참조 검증`.
**사용자가 승인한 파일·항목만** 삭제하고 인덱스·참조를 다시 확인한다. 통합을 이유로
원본 삭제 승인을 생략하지 않는다. 승인 없이는 파일·의미 있는 지식 항목을 제거하지 않는다.
