# 근거를 보존하는 조사

일반 기능 설계·구현에서는 기존 검색·읽기 도구로 필요한 코드와 출력 구간을 먼저 확인한다. 아래 선택 기준에 맞을 때 조사할 프로젝트 루트(기본 `{{PROJECT_ROOT}}`)를 cwd로 두고 공용 CLI `{{PY}} "{{HARNESS_HOME}}/tools/investigation/investigate.py"`를 사용한다(조사 루트는 항상 실행 cwd이며 `/`·홈·그 상위처럼 너무 넓거나 홈 아래 숨김 디렉터리 안이면 거부된다). 입력 경로는 그 루트 기준 상대 경로다. 모델·추론·필수 검증을 유지한다.

- **집계:** 저장된 로그가 크고 건수·대표 사례가 필요한 조사에 선택한다. 짧은 출력이나 오류 한 곳의 주변 줄만 필요하면 직접 읽는다.
- **캐시:** 이미 읽은 근거를 다시 확인해야 할 때 선택한다. 기존 근거로 판단할 수 있으면 재확인 호출을 추가하지 않는다.
- **배치:** 같은 시점에 필요한 독립 로그 집계가 2개 이상이고 개별 호출보다 준비·결과 확인 비용이 줄 때 선택한다. 짧은 파일 몇 개는 기존 도구 호출을 묶어 읽는다.

1. **진단 집계:** 이미 저장된 UTF-8 로그/테스트 출력을 `summary logs/sender.log`로 집계한다. 오류·실패·경고·MQTT·전송·회선 전환의 일치 줄 수, 대표 줄, 생략 수, 원문 경로와 SHA-256이 나온다. 범주는 중복되며 키워드 집계는 진단 결론이나 테스트 통과 판정이 아니다. 원문은 삭제하거나 덮어쓰지 않는다. 원인 판단에 필요한 스택·주변 줄·생략된 근거는 원문에서 추가로 읽는다. 지원하지 않는 형식은 기존 도구를 사용한다.
2. **근거 캐시:** 최초 결과를 읽은 뒤 재확인이 필요하면 반환된 `evidence_key`를 같은 명령의 `--known-key <키>`로 전달한다(배치는 작업별 `known_key`). 입력·의존 파일 전체 해시와 도구 버전이 같을 때만 `unchanged`와 상태를 짧게 반환하고, 변경 시 새 집계가 나온다. 이전 근거를 보지 않았거나 현재 맥락에서 잃었으면 키를 넣지 않는다. 일반 캐시 적중만으로는 출력 토큰이 줄지 않는다. 관련 소스를 `--dependency service/src/example.py`처럼 명시하면 변경·삭제 시 재사용하지 않는다. 캐시는 명시한 파일만 다루므로 추가 파일도 명령에 포함한다. 캐시 적중은 현재 코드의 테스트 통과나 실시간 AWS 상태를 보장하지 않는다. `--no-cache summary ...`로 집계 캐시 없이 실행할 수 있다.
3. **독립 수집 묶기:** 프로젝트 내 JSON 파일에 독립 작업을 선언하고 `batch investigation-jobs.json`으로 한 번에 집계한다. 최대 8개 작업, 동시성 2, 입력 순서로 모든 결과를 반환한다. 서로 의존하는 작업은 별도로 순차 실행한다.

```json
[
  {"name":"sender", "files":["logs/sender.log"]},
  {"name":"tests", "files":["logs/tests.txt"], "dependencies":["app/package.json"], "exit_code":1}
]
```

`exit_code`는 실제 실행에서 확인한 종료 코드만 넣고, 모르면 생략한다(`unknown`). 종료 상태는 현재 호출에서 전달한 값으로 판정하며 캐시에서 가져오지 않는다. 이 CLI는 명령을 실행하지 않는다. 테스트 실행은 기존 권한·훅을 통해 수행하고 stdout/stderr와 실제 종료 코드를 보존한다. 집계 실패나 알려진 nonzero 종료 코드가 하나라도 있으면 CLI도 1로 끝난다. CLI의 0은 테스트 통과를 뜻하지 않는다.

파일/의존성 합계는 작업당 20개·64 MiB, 파일당 32 MiB까지다. 프로젝트 밖·숨김 경로·심볼릭 링크·알려진 인증/설정 보호 경로는 거부한다. 거부된 보호 파일을 복사·이름 변경해서 우회하지 않는다. 로그에 비밀값이 포함될 수 있으므로 승인된 비민감 입력만 사용한다. 이 도구는 비밀값 탐지/삭제 도구가 아니다.

화면 결과가 8,000자를 넘으면 전체 집계는 권한 600인 `full_report` 파일에 보존하고 모든 작업의 상태·종료 코드·오류 요지를 출력한다. `--no-cache`일 때도 큰 결과 보존 파일은 생성한다. `output_truncated`가 있으면 판단에 필요한 작업의 세부 항목을 그 JSON에서 선택해서 읽는다. 전체 보고서를 그대로 다시 출력하지 않는다. 저장 실패 시 상태와 `report_error`를 남기고 1로 끝난다. `omitted_evidence_unavailable`이면 저장 문제를 해결하고 다시 실행하기 전에는 생략된 근거로 결론을 내리지 않는다.

캐시는 프로젝트 `.investigation-cache/`에 디렉토리 700/파일 600으로 저장되며 원문 전체를 복제하지 않는다. 원문은 해당 경로의 파일에 남는다. 캐시는 자동 삭제하지 않으며 정리는 사용자 승인 후 수행한다. 요약으로 해결되지 않으면 필요한 원문을 읽는다. 반복 호출·추가 에이전트·추가 검증을 이 스킬 자체 때문에 만들지 않는다.
